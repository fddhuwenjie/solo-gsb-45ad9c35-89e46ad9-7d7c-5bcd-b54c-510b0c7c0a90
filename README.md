# 针织行式编译台

用 **Python Flask + 原生 JavaScript/SVG** 实现的针织行式编译台：设置起针数后逐行编写针法，
系统按前一行针数展开当前行并推导下一行针数，源码、展开结果与 SVG 图解三方联动。
支持**针法片段**：在定义区写 `名称 = 针法序列`，各行用 `@名称` 引用，一处修改、处处重算。

## 快速启动（单命令）

```bash
docker compose up --build
```

然后访问 **http://localhost:8000**（端口：**8000**，可在 `docker-compose.yml` 的
`ports` 中修改宿主机侧映射）。

### 本地开发（不用 Docker）

```bash
pip install -r requirements.txt
python app.py          # 同样监听 8000 端口 → http://localhost:8000
```

### 运行测试

```bash
python -m unittest -v  # 67 个编译器单元测试，不依赖 Flask
```

## 针法与语法

| 记号    | 含义           | 消耗 | 产出 |
|---------|----------------|------|------|
| `k`     | 下针           | 1    | 1    |
| `p`     | 上针           | 1    | 1    |
| `yo`    | 挂线（空加针） | 0    | 1    |
| `k2tog` | 两针并一针     | 2    | 1    |

- **分组重复**：`(…)xN`，可任意嵌套，如 `(k k, (p, yo)x2, k2tog)x4`。
- **行末重复**：`*…*` 只能出现在整行末尾、不能嵌套。设其内部单次消耗为 `C`、
  当前余针为 `R`：仅当 `C > 0` 且 `R % C == 0` 时，恰好重复 `R / C` 次织到行末；
  否则报错并给出余针数。
- **片段引用**：`@名称`，展开该名称对应的片段（见下节）。
- 分隔符：空白、`,`、`，`、`、`；大小写与全角括号/星号/`@` 均可识别。
- 数字不能直接跟在针法后（`k3` 不合法），重复请写 `(k)x3`。

## 针法片段（定义区 + @引用）

界面上方①为**片段定义区**，每行一条：

```
罗纹   = k k, p p
双罗纹 = @罗纹 @罗纹
镂空   = yo, k2tog
```

行源码中用 `@名称` 引用，可出现在分组与 `*…*` 中：

```
(@罗纹)x6
k k k k, *@镂空*
*@双罗纹*
```

规则：

- 片段可**相互引用**、**前向引用**（先使用后定义），但**不能循环引用**
  （`a → b → a` 会在使用行报错并列出引用链）。
- 片段内**不写行末 `*…*`**（可写分组与 `@引用`）；需要重复到行末时，
  把 `*…*` 写在引用行，如 `*@罗纹*`。
- 分组 `(…)xN` 与行末重复 `*…*` 的次数按片段**实际消耗**计算：
  例如 `镂空 = yo, k2tog` 单次耗 2 针，`k k k k, *@镂空*` 在 10 针上
  先织 4 针、再把 `@镂空` 重复 3 次。
- 修改定义后，所有引用行与后续行**立即重算**。
- **未被引用的片段即使写错也不影响正常行**（定义区行号仅显示为未使用）。
- 缺失引用、循环引用、片段语法错误都**定位到使用它的行与引用位置**，
  并说明所涉定义（错误旁提供「定位定义」按钮跳到定义区对应行列）；
  出错行之后的行按原规则标记「未计算」。

## 编译规则

- 第 1 行消耗「起针数」，之后每行消耗 = 上一行产出。
- 每行消耗必须**恰好**等于可用针数：**不得截断、不得补针**。
- 错误三元组定位：**行号 + 字符列号 + 余针数**，例如
  `第 2 行 · 第 1 列 · '*…*' 单次消耗 3 针，不能整除余针 20（20 % 3 = 2）｜ 余针 20`；
  片段相关错误另附**定义区行列**（`def_line` / `def_col`）与引用链（`chain`）。
- 某行出错后，后续行针数无法推导，标记为「未计算」；修正后自动重算后续所有行。

## 界面联动

- **片段定义**（左上）：`名称 = 针法序列`，行号栏标红错误行、淡化未使用行；
  编辑后 200ms 防抖自动重编译，引用行与后续行立即重算。
- **行源码**（左下）：每行一行针法，可用 `@名称` 引用片段。
- **展开结果**（中）：逐行显示 入→出 针数与展开后的针法序列。来自片段的针法
  以虚线框标记并带 `↗` 按钮：**点击针法定位本次行内引用，点击 ↗ 定位实际针法
  所在定义**；同一片段的多次引用各自映射回本引用处，互不混淆。
- **SVG 图解**（右）：第 1 行在底部，每格一个产出针（k 竖线 / p 横线 / yo 圆圈 /
  k2tog 斜杠），行右标注产出针数；**单击格元回到行内引用，双击格元定位到定义**，
  悬停显示行号、针位与源码/定义位置。
- 光标在源码中移动时，对应行卡片与图解行号同步高亮。

## 逐针来源追溯

在展开结果中点某针的 **「溯」** 按钮，或在图解标题栏打开 **「追溯选择模式」**
后单击任一产出针格元，即以该针为**目标产出针**，沿各行的**实际消耗关系**逐行回溯，
直到**起针针位**或某行 **`yo` 凭空产生的新针**为止：

- `k` / `p` 各承接**一个**前驱针位，`k2tog` 合并**两个**前驱针位，`yo` 没有前驱；
- 分组 `(…)xN`、行末重复 `*…*` 以及片段的**多次引用**都按**每次实际展开**消耗针位，
  即使对应同一处源码（如 `(k2tog)x2` 的两次并针、`@a @a` 的两次引用），
  也分别追溯到各自消耗的不同针位，**不按源码位置合并针目**；
- ⑤ 区给出**可机读的逐针前驱关系文字树**：每跳写明「承接 / 并入上一行第 n 针」，
  并列出全部来源分支（起针第 n 针、或第 n 行第 m 针的 yo 新针），分支配色一一对应；
- 展开列表中目标针橙色描边、其余前驱针蓝框；SVG 中按来源分支着色连线，
  起针针位在底部以彩色三角标出，`yo` 终端以虚线框 + 圆点标出；
- 图解每行最多画 1000 格、展开列表最多列 400 针，**超出而未绘出的针位仍在文字树中
  逐针列出**（标注「图中未绘出」；文字树分段渲染，点「展开前驱分支」继续查看），
  也可用 ⑤ 区的「第 n 行 · 第 m 针」直接选择；
- 追溯树中任意针位的「定位」仍做**单击定位行源码**、「↗ 定义」定位到片段定义，
  与原有单击 / 双击行为一致；
- **编辑源码、定义或起针数时立即清除旧追溯**（无需等重编译返回），避免旧针位编号
  误导；**出错行与「未计算」行没有可选针位**，修正后按新结果重新选择即可；
- 单段追溯最多展开 20000 个针位：超出时对应分支标记「待展开」并附「继续追溯」
  按钮，可逐段展开直至全部起针 / yo 来源；未全部展开前摘要会标注「来源尚未完整」，
  来源分支清单也只覆盖已展开部分，不会误报已完整。

### 追溯操作示例（加针 + 并针 + 片段重复）

起针 **4** 针，定义区：

```
花 = yo, k2tog
收 = k2tog
```

行源码：

```
*@花*
@收 @收
```

展开（片段按实际消耗重复，行末 `*…*` 重复到行末）：

| 行 | 展开针（产出顺序） | 出针 | 每针前驱 `pre` |
|----|--------------------|------|----------------|
| 1 | `yo` `k2tog` `yo` `k2tog`（`@花` 重复 2 次） | 4 | `[]` `[1,2]` `[]` `[3,4]` |
| 2 | `k2tog` `k2tog`（`@收` 引用 2 次） | 2 | `[1,2]` `[3,4]` |

- 选中**第 2 行第 1 针**（`@收` 展开的第一个 k2tog）→ 并入第 1 行第 1、2 针：
  - 第 1 行第 1 针是 **yo**（无输入）→ 来源分支①「第 1 行第 1 针的 yo 新针」；
  - 第 1 行第 2 针是 k2tog → 再并入**起针第 1、2 针**（分支②③）；
  - 两次 `@花`、两次 `@收` 虽指向同一片段定义，追溯仍分别落在
    第 1、2 与第 3、4 针位，互不合并不混淆。
- 选中**第 2 行第 2 针**则同理追溯到第 1 行的第二个 yo 与起针第 3、4 针。

## 项目结构

```
app.py               Flask 入口（GET / 与 POST /api/compile）
compiler.py          词法/语法/片段解析/展开/逐行推导/逐针前驱（纯 Python，可单测）
test_compiler.py     67 个单元测试
templates/index.html 单页界面（定义区 + 行源码 + 展开结果 + 图解）

static/style.css     样式
Dockerfile           python:3.12-slim + gunicorn（8000 端口）
docker-compose.yml   单服务，映射 8000:8000
```

## API

`POST /api/compile`

```json
{
  "castOn": 4,
  "defs": "花 = yo, k2tog\n收 = k2tog",
  "rows": ["*@花*", "@收 @收"]
}
```

响应片段（注意每个产出针的 `pre` 即机读的逐针前驱关系）：

```json
{ "row": 1, "status": "ok", "in": 4, "out": 4,
  "stitches": [
    {"sym": "yo",    "pre": [],      "s": 1, "e": 3, "def": {"line": 1, "s": 4, "e": 6, "name": "花"}, "chain": ["花"]},
    {"sym": "k2tog", "pre": [1, 2],  "s": 1, "e": 3, "def": {"line": 1, "s": 8, "e": 13, "name": "花"}, "chain": ["花"]},
    {"sym": "yo",    "pre": [],      "s": 1, "e": 3, "...": "第二次 *…* 展开，pre 指向各自实际消耗的针位"},
    {"sym": "k2tog", "pre": [3, 4],  "s": 1, "e": 3, "...": "..."}
  ]
}
```

- `defs` **可选**（多行字符串或字符串列表）；缺省时按无片段定义编译，
  响应不含 `defs` 键——未使用片段的旧请求与源码定位行为完全不变。

响应中每行包含 `status`（`ok` / `error` / `blocked`）、`in` / `out` 针数、
`stitches`（含源码列区间 `s`/`e`）或 `error`（`row` / `col` / `message` / `remaining`）。
每个产出针另含 **`pre`：逐针前驱针位数组（1 基，相对本行输入针列）**——
`k`/`p` 为 1 个针位、`k2tog` 为 2 个、`yo` 为 `[]`；第 1 行的 `pre` 指向起针针位，
其后每行指向上一行的产出针位。分组重复、行末重复与多次片段引用均按每次实际展开
消耗的针位记录，不按源码位置合并。`error` / `blocked` 行不含 `stitches`，
因此也没有可追溯的针位。
来自片段的针法额外携带 `def`（`line`/`s`/`e`/`name`，实际针法在定义区中的位置）
与 `chain`（引用链）；此时 `s`/`e` 为本次行内 `@名称` 引用的位置。
片段相关错误的 `error` 额外携带 `def_line` / `def_col` / `def_name` / `chain`。
提供 `defs` 时响应另含 `defs.lines`：定义区逐行状态
（`ok` / `unused` / `error`，附 `name`、`used` 与错误位置）。

安全上限：起针 ≤ 2000，行数 ≤ 500，单行 ≤ 2000 字符，分组重复 ≤ 999，
单行展开 ≤ 20000 针，定义区 ≤ 200 行（超出即报错而非耗尽资源）。
